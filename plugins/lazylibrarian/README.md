# LazyLibrarian connected library

This adapter browses an existing LazyLibrarian Book catalog and reports ebook and audiobook renditions independently. For a Book already in that catalog, it can independently change ebook or audiobook monitoring and request an exact Book search. LazyLibrarian remains the owner of its library and file placement.

Create a Connection with LazyLibrarian's base URL and API key. Enter the absolute ebook and audiobook roots as LazyLibrarian reports them, then map each provider root to a Prismedia library folder that can read the same files. The roots may map to different local folders. Open a Book from Request and switch between Ebook and Audiobook to inspect or link each rendition independently. Both links lead to the same Prismedia Book work.

LazyLibrarian is released continuously, so the adapter reads its `cmd=help` command list on every call instead of pinning one build. Reads need `getAllBooks` and `getAuthor`, and ebook files also need `getFileDirect`. Monitoring and search are offered only when the list shows `queueBook`, `unqueueBook`, and `searchBook` with the format's `type` (`eBook` or `AudioBook`). A read-only API key lists no write commands, so those controls stay unavailable. Builds older than LazyLibrarian commit `a1b52d8c` (2026-09-20) accept `type` on `searchBook` but also search the other format when it is Wanted too.

LazyLibrarian has no API command that reads one book by ID. Each call finds the book once in the full catalog and then reads it through its author (`getAuthor`), including the confirmation after a monitoring change. Only a library read reports a book as removed, and only when the complete catalog no longer lists it. A lookup of an Open Library work that LazyLibrarian has not catalogued reports that the work is not in the catalog. Add it in LazyLibrarian first: its name search cannot establish an exact Open Library work ID.

Ebook files are confirmed with a `getFileDirect` HEAD request. Audiobooks are read from the mapped local folder instead, because LazyLibrarian answers a direct audiobook request, including HEAD, by zipping every audio file in the folder. Map the audiobook root before inspecting audiobooks. For an audiobook in its own folder, every M4B, M4A, and MP3 part in that folder is reported as a separate track. A file directly in the root is reported alone, since the root's other files belong to other works. Prismedia checks every mapped path and size again before import.

Monitoring follows LazyLibrarian's status for each format. Wanted and Snatched count as monitored. Turning monitoring on marks the format Wanted, and it is refused when LazyLibrarian already has the format (Open or Have), because `queueBook` would request another copy. Search is offered only for a Wanted format that is not already snatched; otherwise the request is rejected with the reason. A search acknowledgement means LazyLibrarian started a background search, not that it found a release. The result stays unverified until final mapped files arrive.
